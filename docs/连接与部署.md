# 把 Swarm 装进你已有的 Android agent 应用

这套东西**不需要装 Android SDK、不需要打 APK**。它就是一个 Python 目录，
塞进你手机上那个应用自带的 Linux（Termux、proot-distro、UserLAnd、或者厂商自带的 Linux 环境）就能跑。

---

## 0. 先确认三件事

在每台要参与的机器上，进到它的 Linux shell 里执行：

```sh
python3 -V          # 需要 3.8 或更高
git --version       # 可选，但建议（hub 会多一层提交历史）
ip addr | grep 'inet '   # 看它拿到的局域网 IP
```

没有 python3：

- Termux：`pkg install python git`
- Debian/Ubuntu 系：`apt update && apt install -y python3 git`
- Alpine：`apk add python3 git`

## 1. 把项目拷进去

### 方式 A：`adb push`（手机连电脑）

```sh
adb push swarm /sdcard/swarm-src/swarm
adb push bin/swarm /sdcard/swarm-src/bin/swarm
adb push pyproject.toml /sdcard/swarm-src/pyproject.toml
```

然后在手机的 Linux 里（Termux 中 `/sdcard` 通常是 `/storage/emulated/0`）：

```sh
mkdir -p ~/swarm && cp -r /sdcard/swarm-src/* ~/swarm/
chmod +x ~/swarm/bin/swarm
```

> proot 里访问不到 `/sdcard` 时，先把目录拷到 Termux 的 `$HOME`，proot 里用
> `~/../home/...` 或 bind mount 进去。

### 方式 B：从 hub 机器拉（同一局域网，hub 上开个临时服务）

hub 机器：

```sh
cd /path/to/project && python3 -m http.server 8899
```

手机 Linux：

```sh
cd ~ && wget -qO- http://192.168.1.23:8899/repo.tar.gz | tar xz
```

### 方式 C：直接 `git clone`

```sh
git clone https://github.com/wangzi5151/ai-swarm.git ~/swarm-src
ln -s ~/swarm-src/bin/swarm ~/bin/swarm
```

## 2. 各角色的命令

### 当 hub 的那台

```sh
cd ~/swarm-src
mkdir -p ~/.swarm
nohup ./bin/swarm hub --root ~/.swarm > ~/.swarm/hub.log 2>&1 &
./bin/swarm token --root ~/.swarm      # 主令牌，管理用，抄给自己
```

看板地址就是 `http://<这台机器的IP>:47770/`。第一次打开输入主令牌，
之后用 HttpOnly 会话 cookie，默认 12 小时有效。

给每台干活的机器发独立令牌（推荐）：

```sh
./bin/swarm tokens add 手机A --hub 127.0.0.1:47770
./bin/swarm tokens list --hub 127.0.0.1:47770
./bin/swarm tokens revoke 手机A --hub 127.0.0.1:47770
```

> 为什么放后台：Termux 里退出前台会话进程就没了。`termux-wake-lock` 先执行一下：
> `termux-wake-lock`（需要 Termux:API 或 Termux 内建命令）。

Termux 开机自启（可选）：装 **Termux:Boot**，把启动脚本放到 `~/.termux/boot/start-hub.sh`：

```sh
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
cd $HOME/swarm-src && ./bin/swarm hub --root $HOME/.swarm >> $HOME/.swarm/hub.log 2>&1 &
```

### 当节点的机器

```sh
cd ~/swarm-src
export SWARM_TOKEN='把节点令牌粘这里'
./bin/swarm node --discover --name 手机A --slots 2 \
  --agent cli --cmd 'aider --yes --no-auto-commits --message "{prompt}"' \
  --verify 'python3 -m compileall -q src'
```

- 自动发现失败（路由器隔离）就 `--hub 192.168.1.23:47770`
- 后台跑：`nohup ./bin/swarm node ... >> ~/node.log 2>&1 &`
- `--slots` 别超过这台机器的真实能力：小手机 1~2，电脑 4~8
- `--verify` 会在 agent 交付前在任务目录里跑；退出码非 0 的改动**不会**进主工程
- `--keep-work` 保留任务临时目录，排查 agent 行为时很有用

## 3. 你这台机器上的"已有 agent"怎么接

| 你的应用/Linux 里有什么 | 接法 |
|---|---|
| `aider` | `--agent cli --cmd 'aider --yes --no-auto-commits --message "{prompt}" {files}'` |
| `claude`（Claude Code） | `--agent cli --cmd 'claude -p "{prompt}"'` |
| `codex` | `--agent cli --cmd 'codex exec "{prompt}"'` |
| 本地模型服务（ollama/LM Studio/vLLM） | `--agent http --llm-base http://127.0.0.1:11434/v1 --model <模型>` |
| 自己写的 python 脚本 | `--agent cli --cmd 'python3 /path/agent.py "{prompt}"'` |
| 应用只提供 HTTP API | 写个 5 行的 shim 脚本调它的 API，再 `--agent cli --cmd 'sh /path/shim.sh {prompt}'` |
| 应用只监控某个文件夹 | `--agent cli --cmd 'sh /path/watch-drop.sh {workdir}'`，脚本把任务文件放进它的收件箱并等待结果 |

要点：**它只要能在 `{workdir}` 里改文件，就能接进来。** 不需要它认识 Swarm。

agent 卡住不吐输出也没关系：`cli` 模式有硬超时（按租约算，上限 2 小时），
到点会杀掉整个进程组，任务回到队列。

## 4. 交项目 / 导入已有仓库

新项目：

```sh
./bin/swarm submit -f 需求.md --watch
```

已有仓库：

```sh
./bin/swarm import ./已有项目 --title "接手项目" --plan plan.json \
  --hub 192.168.1.23:47770 --watch
```

导入会先打 tar.gz（尊重 `.gitignore`，跳过 `.git`、`build/` 等），
通过接口传给 hub，所以 hub 可以在另一台机器上。
大仓库建议先写一份 `plan.json`，把每个任务的 `read/write` 开准，
否则默认拆解会按新项目脚手架去切目录。

`plan.json` 里可以给每个任务单独指定：

```json
{"id": "t-api", "title": "接口", "read": ["src/core/**"], "write": ["src/api/**"],
 "deps": ["t-core"], "verify": "pytest -q tests/api",
 "cmd": "claude -p {prompt}", "model": "opus", "agent": "cli"}
```

## 5. 冲突 / 回滚 / 清理

```sh
# 看冲突文件在主工程和节点版本之间的 unified diff
./bin/swarm diff p1 t-api src/api/client.py

# 撤销某次合并（恢复合并前内容；之后被改过会拒绝，--force 强制）
./bin/swarm rollback p1 --task t-api

# 清理没有引用的 blob（默认保护 10 分钟内的新文件）
./bin/swarm gc --hub 192.168.1.23:47770 --token <主令牌>
```

看板上也有"看差异 / 用节点的版本 / 保留主工程 / 回滚"按钮。

## 6. 自检

hub 起来后：

```sh
curl http://127.0.0.1:47770/api/ping        # 有 JSON 就通了
```

节点起来后看日志里有没有：

```
[手机A] 已加入 hub「xxx-hub」，节点 id n-xxxx，2 个槽位，租约 180s
```

不同机器之间连通性（在节点机上）：

```sh
curl http://192.168.1.23:47770/api/ping     # 通 -> 网络没问题
```

不通就依次排查：同一 Wi-Fi？路由器 AP 隔离关了吗？手机热点？防火墙？

---

## 7. 常见坑

- **路由器"AP 隔离/客户端隔离"**：开了的话同一 Wi-Fi 也互相 ping 不通，换手机热点最快。
- **Android 电池优化**：息屏后系统把 Termux 冻住 → 心跳停 → 任务被判掉线。
  设置里给这个 App 关掉电池优化 / 允许后台活动。
- **proot 里 `~` 和 Termux `~` 不是同一个**：令牌文件、日志位置别搞混。
- **端口被占**：`--port 47771 --discovery-port 47772` 换一对，所有节点同步改。
- **时钟不对**：签名带时间戳（±180 秒），两台机器时间差太多会鉴权失败，开一下自动对时。
- **vivo/OPPO 之类会把后台 App 杀掉**：除了电池优化，还要在"后台高耗电/自启动"里允许。
- **令牌丢了/手机丢了**：在 hub 上 `./bin/swarm tokens revoke <名字>`；
  主令牌泄露就停 hub、删 `~/.swarm/token` 后重启（所有节点要换新令牌）。
- **磁盘涨得快**：定期 `./bin/swarm gc`；`.gitignore` 里把构建产物排掉，
  它们就不会进入同步。
